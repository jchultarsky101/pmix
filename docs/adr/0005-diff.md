# ADR 0005: Comparing documents with `pmix diff`

- **Status:** Accepted, 2026-09-07
- **Deciders:** Julian Chultarsky
- **Depends on:** [ADR 0002](0002-semantic-pmi-model.md), [ADR 0003](0003-presentation-pmi-model.md), [ADR 0004](0004-identity.md)

## Context

The purpose of `pmix` is to run it on two or more model files and compare
their PMI. Extraction and identity are in place; this record decides how
the comparison works, what it ignores, and what it prints.

## Decision

### Inputs

`pmix diff <left> <right> [<more>...]`. Each input is either a model file,
which is extracted on the fly, or a JSON document previously written by
`pmix extract`, recognised by its `.json` extension. With more than two
inputs, every later input is compared against the first, so a series of
revisions reads as a series of diffs from the baseline.

### Matching

Records match by `id` (ADR 0004). A record present on one side only is
reported as removed or added. There is no fuzzy fallback in this version:
the identity scheme carries the matching, and its recorded limits (moved or
remodelled parts, unit changes) surface here as remove-plus-add pairs.

### Comparison

Matched records are compared field by field on their JSON form. The
following are excluded because they describe the extraction, not the
design, or change on every export by nature:

| Excluded | Why |
| -------- | --- |
| `source`, `diagnostics`, `unknown` | Describe the extraction. Their counts are reported in the summary. |
| `source_refs`, `parts[].source_ref` | Entity numbers |
| `annotations[].label`, `features[].name` | Vendor names are renumbered by some CAD systems (ADR 0004) |
| `annotations[].geometry`, `annotations[].parts` | Tessellation, including its polyline and triangle counts, changes with the exporting CAD version; the STC 09 re-export re-tessellated every callout |
| `features[].kind`, `features[].geometry`, `features[].members` | The B-rep decomposition changes when a re-export splits or merges faces; the feature's identity already anchors it |
| `annotations[].parts[].polylines / vertices / triangles` | Only present with `--presentation-geometry`; never compared |

Numbers are equal within one part in a million: re-exports print the same
value with different precision.

Id lists (`features`, `semantic`, `presentation`, `views`, `annotations`)
are compared as sets. Everything else is compared by value, with a path
such as `value.value` or `compartments[1].datums[0].modifiers` naming the
field that changed.

Units are compared like any other field and reported, but not normalised:
a file in inches diffed against the same part in millimetres reports every
measure as changed. Normalisation is a later decision.

### Output

Text by default, `--json` for tooling.

Text lists each layer's changes with the record's human label (a
tolerance's or dimension's `text`, a datum's label, a datum system's text,
a view's name, an annotation's text or kind), one line per changed field:

```text
left:  bracket_revB.stp
right: bracket_revC.stp

semantic
  ~ tol:3f9a1c0b7d2e6a48  ⌖ ⌀0.1 Ⓜ | A | B | C
      value.value: 0.1 → 0.2
      text: ⌖ ⌀0.1 Ⓜ | A | B | C → ⌖ ⌀0.2 Ⓜ | A | B | C
  - dim:8dc3737aaa82f437  ⌀35 -0.2/+0
  + dim:2c1e0b9e5a7f4d31  ⌀36 -0.2/+0

presentation
  ~ ann:9e02...  position
      text: … → …

summary: 41 unchanged, 1 changed, 1 removed, 1 added
```

JSON has `schema_version`, `left` and `right` (file names), a `changes`
array of `{layer, collection, id, kind: added|removed|changed, label,
fields: [{path, left, right}]}`, and a `summary` with counts per kind and
the excluded-section counts.

### Exit status

`0` when the documents are equivalent under the rules above, `1` when
they differ, `2` on error. This follows `diff(1)` and lets the command
serve as a check in scripts.

## Alternatives considered

- **Fuzzy matching of unmatched records** by kind and nearby geometry.
  Useful for moved parts; deferred until identity's limits are seen in
  practice, so that the diff stays explainable.
- **Comparing the raw JSON documents with a generic tool.** Works, but
  reports entity numbers, tessellation hashes, and vendor labels as
  changes on every export, which is exactly the noise this record removes.
- **Normalising units before comparison.** Cheap for lengths, ambiguous
  for angles and unit-basis tolerances; deferred.

## Consequences

- A `pmix::diff` module produces a `DiffReport` from two documents; the
  CLI renders it. Both are covered by tests built from synthetic fixtures
  with deliberate edits and from the STC 09 re-export pair.
- The exclusion list is the contract for what counts as a design change;
  extending it is a documented decision, not a tweak.
